이 세 종류는 **고정 정답 하나가 없는 퍼즐 생성기**입니다. 검수할 때는 생성 결과를 개별 인스턴스로 저장하고 고정 표본으로 비교해야 합니다. 다른 퍼즐처럼 동일한 ID에 한 가지 서버 정답을 매핑해서는 안 됩니다.

## 3. 공통 퀄리티 체크 항목

각 퍼즐의 `puzzles/catalog.json → review.checks`에 아래 항목을 기록합니다. 상태는 `pending`, `passed`, `failed` 중 하나이며, 현재는 전부 `pending`입니다.

- **대상 식별:** 결과가 의도한 물체/캐릭터로 보이는가?
- **시각 완성도:** 흑백 대비·실루엣·구도·주요 특징이 충분한가?
- **작은 요소·뾰족함:** 의미 없는 작은 점, 한 칸 돌기, 계단 현상이 있는가?
- **외곽 0줄:** 상하좌우 불필요한 빈 행·열이 있는가?
- **논리적 풀이:** 사람이 힌트만으로 풀 수 있는가?
- **유일해:** 정확한 정답이 하나인지 별도 솔버로 검증했는가?
- **난이도:** 크기뿐 아니라 추론 방식·필요한 시간으로 평가했는가?
- **플레이테스트:** 직접 풀고 불편함·재미·조작 문제를 기록했는가?

### 현재 알려진 확인 사항

- **브레인롯 3종:** 기존 30×30 힌트에 외곽 0줄이 포함될 수 있으므로 검수 필수. 여기서 임의로 잘라내지 않음.
- **토끼·사무라이:** 기존 비트 정답과 힌트의 일치는 검사했지만 원본과의 심미적 일치/논리적 풀이/재미도는 승인되지 않음.
- **겨울 눈사람:** 비공개 정답 자료를 공식 등록 전에 확보·검증해야 함. 유일해에 대한 과거 보고와 실제 독립 검증을 혼동하지 않음.
- **50/75/100:** 무작위 생성 타입. 결과마다 난이도와 품질 차이가 있을 수 있음.
- **하트·고양이·우주선:** 예시/기초 퍼즐이지만 사용자가 품질을 승인한 것으로 취급하지 않음.

## 4. 동일 저장 구조

모든 항목은 공개 카탈로그에 공통 필드를 보관합니다.

`id, name, width, height, kind, origin, difficulty, rows, cols, source, answer, review`

- **문제:** 정답을 공개하지 않고 메타데이터와 가로/세로 힌트를 `puzzles/catalog.json`에 저장.
- **정답:** 고정 퍼즐은 `nono-1bit-msb-v1` 형식, 서버 검증에 필요한 값은 `Firebase /privateAnswersPacked/{id}`에만 보관. 기존 별도 체험 HTML은 제거하며, 원본 정답 자료는 서버/검증용으로만 유지.
- **플레이 기록:** 사용자의 진행 상황과 변경 동작은 퍼즐 정답과 별도로 저장.
- **무작위 생성:** 같은 필드 구조를 사용하지만 `kind=generated`, `rows/cols=null`은 템플릿 정보이며, 실제 숫자는 생성된 **개별 퍼즐 인스턴스**에서 결정됨.

**중요:** 저장 형식이 통일됐다는 사실과 실제 운영 서버에 정답이 등록됐다는 사실은 다릅니다. 정답의 서버 등록·권한·정식 기록 연결은 별도 검증 후 진행합니다.

## 5. 검수 작업 방법

1. `puzzles/catalog.json`에서 퍼즐 ID를 찾습니다.
2. 실제 플레이 화면과 원본 그림을 비교하고 위 8가지 항목을 판단합니다.
3. `review.checks`의 항목별 결과와 `review.notes`를 수정합니다.
4. 모든 필수 평가가 끝나고 인물/그림 식별·유일성·논리 풀이가 확인된 경우에만 `review.status`를 `approved`로 변경합니다.
5. 합격하지 못한 항목은 `failed`로 기록하고 재생성/재검수 대상으로 남깁니다.

기존 퍼즐의 `id`, 원본 정답, 사용자 저장 기록은 검수 과정에서 임의 변경하지 않습니다.
