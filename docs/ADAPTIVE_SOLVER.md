# 적응형 노노그램 논리 풀이기 (2026-11-05)

## 역할
- 행·열 힌트에서 확실히 결정되는 칸만 추론한다.
- 한 줄에 가능한 모든 경우를 직접 나열하거나, 상태 전이 기반 동적계획법(DFA)을 사용한다.
- 상황에 따라 두 방식 사이를 자동 전환한다.
- **논리가 일부만 풀렸다고 여러 정답이라는 뜻이 아니다. 최종 유일해 판정은 기존 CaDiCaL이 담당한다.**

## 방법과 전환
1. 줄의 완성 배치 수 상한이 768 이하일 때: 가능한 전체 배치를 만들고 모두 일치하는 칸을 확정한다.
2. 배치 수가 많을 때: 힌트의 유한상태 자동자(DFA)에서 앞·뒤 방향 도달 가능성을 계산해 확실한 칸을 찾는다. 큰 줄에서 전체 경우를 열거하지 않는다.
3. 줄의 절반 넘게 확정됐고 전체 경우 상한이 3,072 이하로 제한되는 경우: 열거 방식으로 전환할 수 있다. 열거 도중 제한을 넘으면 DFA로 되돌아간다.
4. 행·열 중 이미 알려진 칸이 많고 선택지가 적은 줄부터 검사한다. 가장자리 근접성은 작은 선택 우선 가중치로만 사용한다.
5. 칸이 확정되면 영향을 받는 교차 줄만 다시 검사한다. 모든 행·열을 매번 처음부터 검사하지 않는다.
6. 사용자에게 풀이를 보여줄 수 있도록 추론 한 번에 확정된 칸을 묶어 로그로 기록한다. 각 기록에는 검사한 행·열, 사용한 계산 방식, 후보 수, 확정된 칸 좌표가 들어간다.

## 실행
- Node.js: require('./adaptive-nonogram-solver.js')
- 사이트 브라우저: window.NONO_ADAPTIVE_SOLVER
- solve(puzzle,{maxMs:1000,captureTrace:true,edgePriority:true}) 실행
- 반환 상태: solved / partial / unknown / invalid
- 셀 값: -1 아직 모름, 0 흰색, 1 검은색
- 추론 로그: result.trace 배열의 changes 안에 row, col, value 포함
- puzzle은 size, rows, cols를 가진 기존 퍼즐 객체. [0] 빈 힌트도 지원한다.

## 안전성 검증
- 테스트: tests/adaptive-nonogram-solver.cjs
- 실행: node tests/adaptive-nonogram-solver.cjs
- 길이 5~10의 다양한 힌트/부분 확정 상태를 완전 열거한 결과와 직접 대조한다.
- 5×5부터 100×100까지 고정 시드 3개씩에서 확정된 모든 칸이 원래 정답과 일치하는지 검사한다.
- 원본 무작위 생성기가 유일해를 보장하지 않는 버전의 후보이므로, 논리 풀이 완료 여부와 유일해 증명은 구분한다.
- 2026-11-05 첫 CI에서 1,400개 줄 추론 검사, 2,195개 확정 칸, 943개 로그 단계가 통과했다.

## 초기 성능: 버전 4, 보통 난이도, 시드 100/102/501 3개 평균
| 크기 | 확정 칸 수 | 전체 칸 수 | 전체 풀린 표본 |
|---|---:|---:|---:|
| 5×5 | 21 | 25 | 2/3 |
| 10×10 | 98.7 | 100 | 2/3 |
| 20×20 | 215 | 400 | 0/3 |
| 30×30 | 78 | 900 | 0/3 |
| 50×50 | 17 | 2500 | 0/3 |
| 75×75 | 0.7 | 5625 | 0/3 |
| 100×100 | 0 | 10000 | 0/3 |

이 결과는 논리 풀이기 자체의 성능 표본이고, **유일해 인증된 퍼즐이 아니다**.
100×100에서 확정된 칸이 없는 이유가 알고리즘의 한계인지, 해당 무작위 퍼즐의 복수해 때문인지는 현재 측정만으로 구분되지 않는다.
가장자리 우선 가중치를 켜거나 끄더라도 이 표본에서 확정된 칸 수는 같았다. 어느 쪽이 평균적으로 더 빠른지는 표본을 늘려야 한다.

## 실제 CaDiCaL 동시 비교 (2026-11-05, GitHub Actions, 단일 시드 100)
동일한 v4 무작위 후보 하나씩을 두 방법으로 각각 검사했다. 각 실행은 별도 CaDiCaL 인스턴스를 사용했고 전체 제한은 5초였다.
비교 방식 A: 원래 CNF를 CaDiCaL에서 직접 판단.
방식 B: 새 적응형 풀이기의 확정 칸을 단위절로 추가한 뒤 CaDiCaL에서 판단.
확정 칸은 원래 정답과 모두 대조했지만, 이것만으로 새 알고리즘이 모든 퍼즐에서 절대 안전하다고 단정하지 않는다.

| 크기 | A 상태 / 시간 | B 상태 / 시간 |
|---|---|---|
| 10×10 | 유일해, 10.0ms | 유일해, 5.1ms |
| 20×20 | 복수해, 172.3ms | 복수해, 98.9ms |
| 30×30 | 복수해, 460.8ms | 복수해, 567.7ms |
| 50×50 | 복수해, 2687.5ms | **판정 불가, 5001.8ms** |
| 75×75 | 양쪽 모두 시간 초과 | 양쪽 모두 시간 초과 |
| 100×100 | 양쪽 모두 시간 초과 | 양쪽 모두 시간 초과 |

**판단:** 일부 작은 크기에서는 더 빨랐지만 30×30은 느려졌고 50×50은 오히려 제한 시간 내 판정에 실패했다. 따라서 이 시험 결과만으로 적응형 풀이기를 운영 SAT 검증의 필수 전처리로 연결하면 안 된다. 현재 v6 운영 판단 절차는 그대로 두며, 별도의 5초 한도 및 더 많은 시드에 대한 성능 검증이 필요하다.

- 검증 로그: https://github.com/ishyun1227/nono-web/actions/runs/41997115408

## 2026-11-06 최종 선택: 퍼즐 풀이기 기본 정책

- **확정한 기본 풀이기:** Adaptive 논리 풀이기로 확정할 수 있는 칸을 먼저 끝까지 채우고, 더 이상 논리적으로 진전이 없을 때만 CaDiCaL SAT를 호출한다.
- 고정 25%·50%·75%·90%에서 강제로 넘기는 방식은 기본 정책으로 채택하지 않는다.
- 실제로 Adaptive가 막히는 유일해 퍼즐 18개를 사용한 7가지 방식 × 5회, 총 630회 벤치마크에서 위 조합은 90/90회 완성했다. 논리 단독은 0/90회 완성했다.
- CaDiCaL 단독보다 "논리 막힘 시 호출"이 빠른 퍼즐은 13/18개, CaDiCaL 단독이 빠른 퍼즐은 5/18개였다. 따라서 **모든 퍼즐에 최단 시간임을 증명한 것은 아니며**, 유효성과 운영 단순성을 기준으로 선택했다.
- **중요:** 이 결정은 풀이 전략에 관한 것이다. 랜덤 퍼즐 등록 전 **유일해 인증은 별도로 CaDiCaL의 차단절 UNSAT 판정이 반드시 필요**하다. Adaptive의 완성 여부가 유일해 증명이 될 수는 없다.
- 이번 결정으로 기존 웹사이트 생성 코드가 자동 변경되지는 않는다. 실제 사이트 생성/검사 파이프라인에 풀이 정책을 적용하고 검증하는 작업은 후속 개발 사항이다.
- 자세한 실험 결과: [실제로 논리가 막히는 유일해 18개 비교](NONOGRAM_ACTUAL_STALL_UNIQUE_RANDOM_COMPARISON_20261106.md)

## 2026-11-06 런타임 풀이기 적용

- 구현: [hybrid-nonogram-solver.js](../hybrid-nonogram-solver.js). **Adaptive 논리적 고정점 → 논리가 실제 멈춘 경우에만 CaDiCaL**을 실행해 정답 한 개를 찾는다. 정확한 행·열 힌트 대조와 이전 논리 확정 칸 검증을 거친다.
- 브라우저 비동기 실행: [hybrid-solve-worker.js](../hybrid-solve-worker.js) (실제 CaDiCaL WASM); `NONO_RANDOM_PUZZLES.solveAsync(puzzle,{maxMs:10000})`에서 사용한다. 요청 시간 상한은 10초이며 정체 전에 시간 제한에 도달하면 결과를 `unknown`으로 반환한다.
- 결과 예: `{status:'solved',method:'adaptive_then_cadical',cells:[...],logicSolved:123,satCalled:true,uniqueness:'not_checked'}`. 논리만으로 완성 시 `method:'adaptive'`, `satCalled:false`.
- **정답 하나를 찾는 기능으로 유일해 인증을 대체하지 않는다.** 기존 [random-unique-worker.js](../random-unique-worker.js)가 원래 정답을 차단하는 CaDiCaL SAT에서 `UNSAT`가 나왔을 때만 `unique` 판정을 제공한다.
- SAT 인코더에는 정답 찾기 전용 `encodeForSolve()`를 추가했다. 원래 유일해 증명용 `encode(puzzle,reference)`의 차단절은 삭제하지 않았다.
- 실험/회귀 검사: `tests/hybrid-runtime-solver.mjs`, `tests/browser-hybrid-solver.cjs`, `tests/cadical-integration.mjs`, `tests/async-random-generator.cjs`.
- **적용 범위:** 브라우저 앱 코드에서 비동기 풀이 API를 호출할 수 있게 구현했다. 자동 풀이 버튼이나 이용자 진행 상태·기록 변경은 추가하지 않았다. 난이도·재미도 평가도 아직 별도 작업이다.
