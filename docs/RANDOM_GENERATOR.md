# 이미지와 도형 구조 없이 랜덤 배치하는 노노그램 v4 (2026-11-03)

## 이번 버전의 핵심
- 크기·시드를 선택하면 **그림, 곡선, 고리, 분기점, 도형을 만들지 않고 각 칸의 위치를 무작위로 구성**한다.
- 논문에서 풀이 과정을 요구하지 않는 유일한 정적 항인 검은/흰 칸 균형 `B=4*b*w/(b+w)^2`만 참고한다.
- 전체 칸의 47~53%를 검은색으로 정하고, 이 수만큼 무작위 위치를 채운다.
- 0 힌트를 사용하지 않기 위해 행과 열마다 최소 한 칸의 검은색을 **처음부터** 배정한다. 이를 위해 열 번호를 Fisher–Yates로 무작위 섞어, 각 행에 한 칸씩 배치한다. 이후 남은 좌표를 Fisher–Yates로 다시 섞어 나머지 검은 칸을 채운다.
- 위 행·열 비우지 않기 조건 때문에 모든 비트 배열 중에서 **수학적으로 완전히 균일한 표본**은 아니다. 하지만 시각적 형태나 사물과의 유사성을 의도적으로 만들지 않고 모든 추가 칸의 위치를 무작위로 선택한다.
- 후보를 여러 개 생성해서 골라내는 과정, 자동 풀이, 풀이 기반 점수 측정은 하지 않는다. F 점수는 `null`이다.

## 난이도는 아직 미검증
- 사이트에 기존 크기/난이도 선택 UI를 유지한다.
- v4에서는 난이도 값이 **선택·표시·저장용 메타데이터**이며, 쉬움/보통/어려움/전문가별로 논리적 풀이 난이도가 다르도록 보장하지 않는다.
- 정답 유일성, 논리만으로 풀이 가능한지, 실제 재미도 역시 미검증이다. 특히 대결에서 다른 유효한 정답이 나오는 문제는 현재 서버의 기준 마스크 비교 구조상 가능성이 있다.

## 이전 버전 및 대결/협동
- v1: 기존 경로/패턴 구성, v2: 풀이 기반 수정, v3: 균형형 추상 패턴 구성은 **그대로 복원**한다.
- 새로 생성한 퍼즐은 `designVersion:4`로 기록한다. 예전에 저장하거나 진행 중인 퍼즐을 바꾸지 않는다.
- 방 메타데이터 `randomSpec.version:4`를 사용하므로 모든 플레이어가 동일 시드로 같은 힌트/기준 정답을 재구성한다.
- 기존 `coopMoves`/`raceMoves` 변경 로그 방식은 변경하지 않는다.
- **운영 Firebase 규칙을 먼저 배포**해야 v4 랜덤 퍼즐로 새 대결/협동 방을 만들 수 있다. GitHub 코드 변경만으로 운영 Firebase 규칙 배포는 완료되지 않는다.
- 공개 시드와 알고리즘만으로 정답을 재구성할 수 있으므로 치트 방지형 공식 랭킹용으로는 적합하지 않다.

## 논문 근거
Milo Roucairol · Tristan Cazenave, *Generating Difficult and Fun Nonograms* (CG 2024).
https://www.lamsade.dauphine.fr/~cazenave/papers/Nonogram2024.pdf

논문 전체의 재미도 공식은 `F = (4*b*w/s² - k)*u + 5 - max(d,5) - g²`이고,
이번 버전에서 사용하는 것은 `4*b*w/s²`뿐이다. 균형 지표를 높게 만든다고 인간의 재미를 보장하지는 않는다.
