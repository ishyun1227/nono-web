# 이미지 없는 랜덤 노노그램 — 생성 방식 v3 (2026-11-03)

## 현재 적용하는 논문 변수
참고 문헌: Milo Roucairol · Tristan Cazenave, *Generating Difficult and Fun Nonograms* (Computers and Games, 2024).
원문: https://www.lamsade.dauphine.fr/~cazenave/papers/Nonogram2024.pdf

기존 논문의 재미도 추정식:
`F = (4*b*w/s² - k)*u + 5 - max(d,5) - g²`

- **새 퍼즐 v3은 F 전체를 계산하지 않는다.** 풀이 도중 필요한 `k,u,d,g`와 사용자 평가를 모두 제외했다.
- 생성 전에 설계에 고려하는 정적 항은 `B = 4*b*w/s²`뿐이다. 검은 칸 `b`와 흰 칸 `w`의 균형 지표이며, 총 칸 `s=b+w`이다.
- `B`는 검은 칸 50%, 흰 칸 50%에서 1로 최대화되지만, 이것만으로 재미나 유일해 또는 논리적 풀이 가능성을 보증하지 않는다.

## v3 퍼즐 생성
1. 크기와 난이도, 시드를 받아 연속 가로·세로 곡선 경로 및 고리·분기·계단형 무늬를 구성한다. 난이도는 경로의 굽힘 빈도·폭·구성에만 영향을 주며 정식 검증 등급이 아니다.
2. 기하학적 경로와의 거리를 이용해 매 칸의 매끄러운 구성 점수를 구한다. 각각의 가로 행과 세로 열이 비지 않도록 두 경로를 앵커로 포함한다.
3. 검은 칸 목표 비율을 시드에 따라 **47~53%** 사이로 정하고, 구성 점수가 높은 칸부터 목표 칸 수만큼 채운다. 픽셀 수 `b`와 `w`의 균형을 생성 규칙에 직접 넣는다.
4. 채운 칸에서 가로·세로 힌트를 만들고 시드·크기·난이도·버전을 저장한다. **후보를 여러 개 만들거나, 자동 풀이기를 실행하여 F 점수로 재생성하거나 선별하지 않는다.**
5. v3은 `paperFunScore: null`, `paperDifficultyScore: null`, `paperSolverStatus: 'not_evaluated'`로 저장된다. UI에 예전 F 평가값/미평가 뱃지를 표시하지 않는다.

## 저장 및 멀티플레이
- 신규 퍼즐은 `designVersion:3`; 기존 저장된 v1과 v2는 이전 생성 규칙 그대로 재현한다. 과거 퍼즐에 새 규칙을 소급 적용하지 않는다.
- 대결·협동 방에 `randomSpec: {version,size,seed,difficulty}`를 저장한다. 모든 사용자가 동일한 시드로 동일한 힌트·정답을 복원한다.
- 사용 중인 `coopMoves`, `raceMoves` 등 변경값 저장 방식을 변경하지 않는다.
- **운영 Firebase 규칙에 v3 허용 조건을 먼저 배포**해야 새 랜덤 멀티플레이 방이 작동한다. GitHub 코드 업데이트만으로 Firebase가 배포되지는 않는다.
- 공개 시드를 가진 사용자는 정답을 재현할 수 있어 치트 방지형 공식 경쟁으로 취급해서는 안 된다.

## 범위와 검증
- v3은 평가를 건너뛰므로 **논리적 풀이 가능성, 정답 유일성, 실제 체감 난이도, 재미도는 아직 정보 없음**. 이 항목들은 보장하지 않는다.
- 구조 검사는 사용자 재미 평가가 아니라 생성된 힌트와 실제 생성 마스크의 일치 여부 및 0 힌트 없는지 확인하는 기술적 정확성 검사이다.
- `node tests/random-puzzles.cjs`: 9종 크기 × 4종 난이도 × 3종 시드 = 108개 생성/힌트/균형 검증, v1·v2 호환성.
- `npm run test:multiplayer`, `npm run test:browser`는 Firebase 에뮬레이터/브라우저용 검사이며 v3 운영 사이트에 대한 실측 완료를 의미하지 않는다.
- Firebase RTDB 규칙 변경 후 Cloudflare 사이트 배포와 실제 사용자 2명 대결/협동 검증이 필요하다.
