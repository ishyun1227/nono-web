# 그림 없는 노노그램: 구성형 랜덤 생성 및 멀티플레이 (2026-10-31)

## 구현 목표
그림을 변환하거나 무작위 픽셀을 뿌린 다음 품질 점수로 거르는 방식 대신,
**처음부터 풀이할 패턴의 구조를 배치**합니다. 연속된 가로·세로 경로, 곡률,
교차점, 고리, 분기점, 계단형 곡선, 국소 빈 공간을 하나의 구성으로 만듭니다.
크기·난이도·무작위 seed가 해당 구조를 결정하고 한 번의 생성으로 힌트가 정해집니다.
기존 후보 수백 개를 뽑는 거절/품질 점수 루프는 제거했습니다.

이것은 **재미를 고려한 생성 규칙**이지, 모든 사용자가 재미있다고 평가하거나
난이도가 정확하다는 것을 검증한 결과가 아닙니다. 100% 재미를 보증하는
공식 점수는 없습니다. 논리적 풀이 가능성, 유일해 및 완주/재시도율은
아직 보장되지 않습니다. 멀티플레이에서 같은 힌트에 서로 다른 정답이
있을 경우, 현재 서버는 생성된 기준 답안과 일치하는 판만 최종 승인하므로
문제가 발생할 수 있습니다. 이 제한을 해결하려면 유일해 보증 또는
행·열 일치 검증을 하는 신뢰 가능한 서버 로직이 필요합니다.

## 사용
- 기본(네온) 테마에서 **혼자 풀기·대결·협동** 선택.
- **크기**: 작음 5/10, 중간 15/20, 큼 25/30, 거대 50/75/100 (각 그룹 안에서 크기 랜덤 선택).
- **난이도**: 쉬움/보통/어려움/전문가. 선 두께·굽힘·분기/고리·내부 빈 공간을 단계별로 조절합니다.
- 혼자 풀기: **새 랜덤 퍼즐 생성**을 누르면 기존 게임 엔진에서 즉시 시작합니다.
- 대결·협동: **랜덤 퍼즐로 방 만들기**를 누르면 생성된 퍼즐로 방 생성 후 초대/공개 로비 입장이 됩니다.
- 빠른 매칭은 **같은 크기 및 난이도의 다른 사람의 랜덤 방**에 합류할 수 있습니다.
  참가자의 처음에 선택했던 랜덤 퍼즐 ID가 달라도 방에 들어가면
  **방의 생성 seed/힌트**를 사용하도록 교체합니다.

## 참가자 동기화/저장
- RTDB `rooms/<code>/meta/randomSpec`: seed, size, difficulty, version. 방 생성자만 설정하고 바꿀 수 없습니다.
- 수신자는 공유 seed로 정확히 같은 행·열 힌트를 재구성합니다.
- RTDB `roomAnswers/<code>`: 방장만 최초 1회 생성 정답 마스크를 기록하고 읽기는 모든 사용자에게 차단.
  기존 `privateAnswers`, `privateAnswersPacked` 및 진행 기록은 변경하지 않습니다.
- 대결 최종 상태 `finishedAt`은 서버의 비공개 정답과 일치해야 성공합니다.
  등록된 퍼즐의 기존 서버 검증도 유지합니다.
- 협동과 대결의 칸 변경 로그는 기존 `coopMoves` 및 `raceMoves` 바이너리 델타를 그대로 이용합니다.
- 참가자는 방 코드 링크로 재입장할 수 있고, 해당 방의 퍼즐 seed를 서버에서 복원합니다.
  개인 로컬 퍼즐 목록은 브라우저에 최대 100개 보관합니다.

## 안전한 배포 및 제한
- `main`에 코드를 올리는 것만으로 운영 Firebase 데이터베이스 규칙은 바뀌지 않습니다.
- **반드시 `database.rules.json` 규칙을 먼저 운영 Firebase에 배포해야 합니다.**
  구버전 규칙은 생성 랜덤 `puzzleId`와 비공개 방 정답 경로를 거절합니다.
- Firebase 관리자 키가 이전 대화에 노출된 적 있어, 기존 키로 자동 운영 배포하면 안 됩니다.
  새로 발급·보호한 권한으로 배포하세요.
- 공개 생성 seed와 공개 JavaScript 알고리즘으로 정답을 재현할 수 있으므로,
  생성 퍼즐의 대결을 **치트 방지형 공식 랭킹**으로 취급해서는 안 됩니다.
- 가입/로그인, Firebase 온라인 연결이 필요하며 `record` 모드 공식 기록 경쟁에는 아직 랜덤 생성이 없습니다.
- 웹 배포는 GitHub `main` 후 Cloudflare 빌드가 활성화된 경우 진행됩니다.
  실제 운영 규칙 및 동시 접속 검증 여부는 별개로 확인해야 합니다.
