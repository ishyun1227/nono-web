# 그림 없는 노노그램: 재미도 계산과 구성형 생성 (2026-11-03)

## 근거
- Milo Roucairol · Tristan Cazenave, **Generating Difficult and Fun Nonograms** (Computers and Games, CG 2024), pp. 119–129.
- 저자 원문: https://www.lamsade.dauphine.fr/~cazenave/papers/Nonogram2024.pdf
- §2: 행·열 후보들의 공통 칸을 이용해 진행하고, 필요하면 모순 기반 edge solving을 최대 1–3회 적용.
- §3: 사각형 단위의 값 변경을 탐색하는 Monte Carlo / 탐색 기반 생성.
- §4.3: `D = n + 50 * sqrt(g) + 10 * d`.
- §4.4: `F = (4 * b * w / s² - k) * u + 5 - max(d, 5) - g²`.
- **논문의 F는 사람에게서 수집한 재미 평가가 아니라 검증되지 않은 추정식**이며, 아래 구현은 논문 풀이기 코드를 복제한 것이 아니라 논문 원리에 따른 자체 구현이다.

## 구현 v2
1. 이미지와 독립적으로 연속 경로·곡선·교차점·고리·분기점 등을 먼저 설계한다. 5–10칸 크기는 별도 선 추가로 유일해 개선을 시도한다.
2. 5–30칸에서는 `random-puzzle-solver.js`가 행·열 힌트에 대해 유한상태기계 전후방 DP로 공통 확정 칸을 구하고, 변경된 칸이 교차하는 행·열을 우선 확인한다.
3. 더 진행할 수 없다면 어려움/전문가에서는 이중 가정을 금지한 모순 기반 흰 칸 가정을 각각 최대 2/3회 시도한다. 쉬움/보통에서는 사용하지 않는다.
4. 풀이 기록에서 `n`(확정 이동 횟수), `g`(성공한 모순 기반 가정), `d`(이동 후 다음 7개 행/열에서 확정 이동을 못 찾은 경우), `u`(확정 칸 수의 서로 다른 이동 길이), `k`(그 길이의 Pearson 첨도), `b/w/s`를 계산한다.
5. 기존 결과를 버리고 다시 만드는 대신, **같은 초기 퍼즐을 소규모 사각형 단위로 바꾸어** 측정된 F가 개선되는 수정만 유지한다. 목표 난이도 보정은 게임 자체 설정값이며 **논문에서 제시한 등급 경계가 아니다**.
6. `paperFunScore`와 `paperDifficultyScore`는 **논문 식 기반 추정 수치**를 그대로 저장한다. 5점 만점 점수나 플레이어 만족도 수치로 변환하지 않는다. 미완료/풀이불가/동일 길이만 나오는 경우 등으로 지표가 계산되지 않으면 `null`이며 UI는 '평가 미완료'로 표시한다.

## 보장과 제한
- **논문의 원본 인간형 풀이기와 이동 순서가 완전히 같지는 않다.** 따라서 F 수치가 논문 표의 값과 정확히 비교 가능한 것은 아니다. `method = paper-inspired-line-dp-v1`로 기록한다.
- 풀이기가 `solved`를 반환한 경우, 모든 셀은 힌트로부터 타당한 논리적 추론(모순 가정 포함)으로 확정되므로 결과는 유일하다. 다만 전체 생성 결과가 `solved`라고 보장되지는 않는다.
- 구현은 `30×30`까지 자동 평가한다. 50×50·75×75·100×100은 계산량이 커서 `not_evaluated` 및 점수 없음으로 표시한다. 대형 퍼즐은 정답 유일성/논리 난이도 미검증이다.
- 생성기는 동일한 `size + difficulty + seed + version`에서 동일 정답·힌트를 만든다. 브라우저의 짧은 캐시는 계산만 재사용하며 결과는 바꾸지 않는다.
- 기존 `designVersion:1` 퍼즐과 Firebase `randomSpec.version:1` 방은 레거시 구성 규칙을 유지한다. 신규 퍼즐과 방은 **버전 2**로 생성한다. 생성 모듈을 로드하지 못하면 v2는 생성하지 않는다.
- 대결·협동은 방의 seed/size/difficulty/version을 Firebase에 기록하고, 다른 플레이어는 그 데이터를 바탕으로 퍼즐을 복원한다. `roomAnswers`는 읽기를 차단하지만 **공개 seed를 가진 사용자는 생성 알고리즘으로 답을 재현할 수 있어 치트 방지는 아니다.**
- 이론적 재미·유일성 검증과 실제 운영 검증은 별개이다. 기존 서비스 기록을 지우지 않는다.

## 배포
1. **운영 Firebase 규칙을 먼저** `database.rules.json` 최신 버전으로 배포해야 한다. v2 랜덤 방 메타데이터가 새 규칙을 요구한다.
2. 이후 Cloudflare 사이트를 빌드한다. `tools/build.cjs`가 `random-puzzle-solver.js`와 `random-puzzles.js`를 함께 포함한다.
3. 서로 다른 계정 2개로 솔로, 대결, 협동, 재입장, 양쪽 힌트 일치, 서버 완료 판정을 실제 테스트한다. GitHub 커밋만으로 운영 배포가 완료된 것이 아니다.
4. 기존에 노출된 서비스 계정 비밀키로 자동 운영 배포하지 않는다.
