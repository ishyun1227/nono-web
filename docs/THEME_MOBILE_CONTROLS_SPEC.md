# NONO 테마별 모바일 조작 패드 — 디자인·입력 분리 명세

> 문서화: 2026-10-29 (KST)  
> 상태: **요구사항/디자인 방향 기록 완료, 기능 구현·시각 QA·공개 배포는 미완료**  
> 추적 이슈: [#7 테마별 모바일 조작 패드 스킨](https://github.com/ishyun1227/nono-web/issues/7)

## 1. 사용자 결정과 목적

1. **웹 테마를 변경하면 모바일 조작 패드의 시각적 스타일도 테마에 따라 변경한다.**
2. 버튼의 **입력 의미는 테마와 무관하게 유지**한다. 테마 스킨은 외형/애니메이션만 담당한다.
3. 사용자 커스터마이징(버튼 위치, 그룹·개별 오프셋, 크기, 투명도, 고정/플로팅 조작, 외부 게임패드 매핑)은 **테마 변경 시 유지**한다.
4. 사용자가 원하면 **기본 패드로 외형을 고정**할 수 있게 한다.
5. 기존 논의한 **저가 색상 테마 / 고가 전체 월드 테마** 차이를 패드에도 일관되게 적용한다.
6. **자동차/레이싱 콘셉트는 새로운 시안**이다. 현재 코드의 테마 목록에 자동차 테마는 없으므로 구현·상품 출시로 간주하면 안 된다.

## 2. 현재 코드·기존 기능 (확인됨)

| 영역 | 소스 및 현 상태 |
| --- | --- |
| 테마 목록/선택/미리보기/취소 | `themes.js` — `id`, `tier: color/world`, `document.body.dataset.nonoTheme`, 임시 세션 체험 |
| 모바일 버튼 및 물리 게임패드 입력 | `controller-input.js`, `controller-input.css` — `#nono-mobile-pad`, `data-nono-input` |
| 개인별 패드 설정 | `controller-customization.js`, `controller-customization.css` — `NONO_INPUT_CUSTOM`, `localStorage['nono-input-settings-v1']` |
| 진행 순서·완료 기준 | `AGENTS.md`, `docs/DEVELOPMENT_ROADMAP.md` — 핵심 기능 안정화 후 월드 테마 확장 |

현재 커스터마이징에 **고정 십자키/플로팅 조이스틱**, 투명도 **20–100%**, 크기 **65–150%**, 방향 패드/동작 버튼 그룹 위치, 4개 동작 버튼별 오프셋, 게임패드 매핑 및 데드존이 존재한다. `localStorage` 저장이므로 다른 기기/브라우저로 자동 동기화되지 않는다. 테마 스킨 기능은 아직 미구현이다.

## 3. 디자인 콘셉트 매핑

| 콘셉트 | 패드 외형·조작 반응 | 현재 테마와의 관계 |
| --- | --- | --- |
| **자동차 / 레이싱** | 4방향 셀 이동이 가능한 **핸들 모티프 패드**, 카본·메탈 버튼, 빨강/주황 LED 포커스, 계기판식 눌림 상태 | **신규 시안**. 테마 ID와 상점 상품 등록은 별도 승인·구현 필요 |
| **아케이드 / 8비트** | 픽셀 십자키, A/B처럼 보이는 동작 버튼, 낮은 프레임 도트 애니메이션 | `arcade` 월드 테마의 **제안 스킨** |
| **사이버 / 우주** | 반투명 홀로그램 스틱·버튼, 네온 링, 짧은 발광 효과 | `cosmos` 월드 테마의 **제안 스킨** |
| **감성 / 판타지** | 따뜻한 색의 둥근 버튼, 부드러운 눌림 및 패널 장식 | `library`, `enchanted` 등에 **개별 차별화 필요** |
| **기본 / 미니멀** | 고대비 일반 십자키와 단순한 칠하기·X 버튼 | `neon`의 기본 스킨. 수동 기본 고정 시에도 사용 |
| **색상 전용** | 형태·조작 위치 유지, 색상 토큰/테두리/강조색만 변경 | `aurora`, `pastel`, `retro`, `forest` 등 `tier:color` |

위 표는 **디자인 제안**이며 개별 테마별 최종 시안 확정·코드 반영을 의미하지 않는다. 실제 ID/티어는 항상 최신 `themes.js`를 기준으로 한다.

### 자동차 테마 특별 주의
- 핸들 디자인이라도 좌·우만 있는 실제 운전 스티어링이 아니라 **위/아래/왼쪽/오른쪽 네 방향의 셀 이동**이 명확해야 한다.
- 액셀/브레이크처럼 보이는 버튼에 **칠하기 / X 표시 / 지우기 / 취소** 기능명을 분명히 제공한다. 겉모양 때문에 기능 의미를 숨기면 안 된다.
- 실제 퍼즐판의 힌트 숫자/격자와 터치 영역을 가리지 않고, 과한 모션·글로우를 피한다.

## 4. 상호작용 및 설정 사양

- **테마 변경·미리보기:** 스킨만 즉시 변경하며 `NONO_INPUT_CUSTOM`의 개인 값은 덮어쓰지 않는다. 미리보기 취소 시 테마 스킨도 즉시 이전 상태로 복귀한다. 기본 테마로 복귀하면 기본 스킨을 적용한다.
- **패드 외형 선택:** `테마 전용(기본값)` / `기본 패드`. 테마 전용으로 설정한 경우 스킨을 제공하지 않는 테마는 기본 패드로 폴백한다.
- **패드 입력 방식:** 고정 패드 및 손가락 따라오는 플로팅 조이스틱 모두 같은 스킨 정책. 레이싱 핸들 모티프를 쓰더라도 `mode` 전환과 방향 이벤트 경로를 바꾸지 않는다.
- **위치/크기/투명도:** 설정 페이지에서 기존 값 유지; 테마별 이미지·장식에 따라 터치 가능 영역이 축소되지 않게 한다.
- **키보드/물리 컨트롤러:** PC·모바일 모두 현재의 `standard Gamepad` 입력 및 사용자 매핑 유지. 연결되지 않았을 때 컨트롤러 설정을 강제 노출하지 않는다.
- **작은 화면:** 안전 영역 및 가로/세로 모드 대응. 퍼즐판 자동 맞춤/스크롤 정책과 충돌하지 않도록 실제 패드 영역을 계산한다.
- **접근성:** 터치 목표 크기·명확한 라벨·대비·눌림 상태·모션 감소(`prefers-reduced-motion`) 및 빠른 연속 입력을 고려한다.
- **가격·상점:** 색상 테마는 패드 색상 위주, 월드 테마는 패드 형태까지 가능. 실제 포인트·구매·소유 검증은 별도 미구현이므로 구매 완료처럼 표시하지 않는다.

## 5. 권장 구현 구조 (설계 제안)

```text
themes.js                         실제 테마 id / tier / 미리보기 상태의 소유자
controller-input.js               키·터치·게임패드 입력 이벤트 (변경 최소화)
controller-customization.js       사용자의 위치/크기/투명도/모드/매핑 저장
controller-customization.css      공통 패드 레이아웃 + CSS 변수
[신규] theme-pad-skins.css         data-nono-theme 기반 tier별 스킨 토큰/외형
[선택] theme-pad-skins.js          외형 선택 옵션·스킨 전환 및 폴백
```

- 입력 동작은 기존 `data-nono-input`에 연결된 상태로 유지하고, 스킨은 CSS 변수·클래스·SVG 장식으로 표현한다.
- 애니메이션 상태는 입력 상태(`.is-held`)를 재사용한다. 외형을 위해 실제 입력 버튼을 복제하지 않는다.
- 생성 시안 이미지의 일부를 잘라 클릭 가능한 UI로 쓰지 말고 오리지널 SVG/CSS 자산으로 구현한다.
- 기존 `nono-input-settings-v1` 키는 호환성을 보존한다. 새로운 `padAppearance` 필드는 유효성 검증 및 구버전 폴백과 함께 추가한다.

## 7. 완료 판정

**문서화 완료**와 **실제 기능 완성**을 혼동하지 않는다. 패드 스킨 변경을 포함한 UI/기능 테스트, 실기기 시각 확인, 공개 배포가 모두 확인되기 전까지 상태는 `미구현 / 검증 전`이다.
