# SAT 방식과 기존 유일해 검사기 비교 (2026-11-03)

## 목적
새로운 무작위 노노그램 퍼즐의 **유일해 검증 정확성과 속도**를 비교한다.
재미도(F)나 체감 난이도는 평가하지 않는다.

## 구현
- 기존 검사기: `random-puzzle-solver.js`의 `countSolutions`. 행·열 DFA 제약 전파와 깊이우선 분기로 최대 두 해를 검사한다.
- 비교용 검사기: `sat-nonogram-solver.js`. 행·열 DFA를 CNF 논리식으로 변환하고, 생성 당시 정답과 최소 1칸 다르도록 하는 **차단 절(blocking clause)**을 추가한다. 실험적 JavaScript DPLL(두 리터럴 감시) 구현으로 SAT/UNSAT를 판정한다.
- `SAT`면 다른 답이 있어 **복수해**, `UNSAT`면 원래 답밖에 없어 **유일해**이다. 탐색·메모리 예산을 소진하면 `unknown`이며 유일해로 인정하지 않는다.
- SAT 검사는 **브라우저 운영 생성기에 연결하지 않았다**. 현재 v5의 출제 승인 판정은 기존 검사기 그대로다.
- 이 테스트는 **산업용 CDCL SAT 솔버(MiniSat, Kissat 등)를 사용한 측정이 아니다**. 따라서 모든 SAT 솔버가 느리다는 결론을 내릴 수 없다.

## 독립 정확성 테스트
- `node tests/sat-uniqueness.cjs`: 무작위 5×5와 10×10 총 **50개** 퍼즐을 별도 완전탐색 풀이기와 비교했다.
- 기존 검사기: 50개 전부 정확히 판정.
- SAT 방식: **25개 판정 일치, 25개는 예산 초과(unknown)**. 판정한 결과에는 불일치가 없었다.
- 단순 유일해·복수해·잘못된 참조 정답·검사 예산 초과 사례도 검사했다.

## 속도 비교
`node tests/benchmark-sat-uniqueness.cjs`. 같은 v4 무작위 퍼즐, 난이도 보통, 크기별 고정 시드 4개, SAT는 최대 1,500 탐색 노드. 아래는 V8 실행 환경에서의 소규모 1회 벤치마크로, 실제 모바일 브라우저·배포 서버의 처리 시간을 뜻하지 않는다.

| 크기 | 기존 완료 | SAT 완료 | 기존 평균(ms) | SAT 평균(ms) |
|---|---:|---:|---:|---:|
| 5×5 | 4/4 | 4/4 | 1.00 | 4.00 |
| 10×10 | 4/4 | 0/4 | 2.50 | 12.75 |
| 15×15 | 4/4 | 0/4 | 13.25 | 20.25 |
| 20×20 | 4/4 | 0/4 | 58.00 | 37.75 |
| 25×25 | 4/4 | 0/4 | 139.75 | 52.50 |
| 30×30 | 4/4 | 0/4 | 383.75 | 81.75 |

**주의: SAT의 20×20 이상 표시 시간이 더 짧은 것은 먼저 검사를 포기했기 때문**이며, 해 판정까지 빨랐다는 뜻이 아니다.

## 결정
- **현재 v5 생성기의 기존 유일해 판정을 유지한다.**
- SAT/CNF 검사는 독립적으로 유지해 테스트·연구용으로 사용한다. SAT가 유일해라고 검증했지만 기존 검사기가 다르게 판정하는 경우는 버그로 취급해야 한다.
- 유일해 보장을 위해서는 `unknown`인 퍼즐을 등록하지 않는 정책을 그대로 유지한다.
- SAT 성능 향상을 논의할 때는 더 강한 제약 전파, 충돌 절 학습(CDCL), 또는 검증된 SAT 솔버를 별도 벤치마크한 뒤 교체 여부를 결정한다.

## 실행
```bash
node tests/random-puzzles.cjs
node tests/sat-uniqueness.cjs
node tests/benchmark-sat-uniqueness.cjs
```

GitHub Actions `.github/workflows/random-puzzles.yml`에는 무작위 퍼즐 회귀 검사와 SAT 독립 정확성 검사를 포함한다. GitHub 작업 반영은 운영 사이트 배포와 별개다.

## 2026-11-04: 퍼즐당 최대 5초 SAT 검사 (거대 퍼즐 포함)

동일한 `version:4` 무작위 배치, 난이도 `보통`, 시드 `100`을 사용한 크기별 **단일 샘플**이다.
`sat.check`에서 `maxMs:5000`, `maxNodes:10000000`, `maxVisits:100000000`,
`maxVariables:700000`, `maxClauses:1600000`을 사용했다.
실제 시간 측정은 JavaScript V8 실행 환경에서 `Date.now()`로 수행했다.

| 크기 | 검사 경과 | 결과 |
|---|---:|---|
| 5×5 | 13ms | multiple (복수 정답) |
| 10×10 | 5000ms | unknown (time_budget) |
| 15×15 | 5001ms | unknown (time_budget) |
| 20×20 | 5001ms | unknown (time_budget) |
| 25×25 | 5002ms | unknown (time_budget) |
| 30×30 | 5001ms | unknown (time_budget) |
| 50×50 | 5000ms | unknown (time_budget) |
| 75×75 | 5003ms | unknown (time_budget) |
| 100×100 | 5006ms | unknown (time_budget) |

75×75의 초기 실험에서 재귀 호출 한도 초과가 발견되어, SAT DPLL의 탐색을 명시적인 반복문 스택으로 수정한 후 75×75·100×100을 다시 시험했다.
100×100은 이 구현에서 약 **420,878개 변수**, **821,157개 CNF 절**이 생성되었다.
5초 근처의 수 ms 초과는 체크 간격으로 인한 오차다.

**해석 및 한계**
- 10×10 이상에서 5초 내 SAT 판정을 완료하지 못했다. `unknown`은 유일해 또는 복수해의 증거가 아니다.
- 샘플은 각 크기 1개이므로 성공률의 통계적 추정치는 아니다.
- 직접 작성한 **기본 DPLL SAT 구현**의 결과이며, 산업용 CDCL SAT 솔버의 성능을 보여주지는 않는다.
- 운영 v5 랜덤 퍼즐 생성에 쓰는 기존 검사기 `countSolutions`는 변경하지 않았다.
- 재현 명령: `node tests/benchmark-sat-five-seconds.cjs`
